# 分年级时间结构（多套作息）方案

> 状态：方案已定，计划 v1.5 实现。本文档记录设计决策，供实施时对照。

## 背景与问题

当前 `TimeConfig`（daysPerWeek / periodsPerDay / morningPeriods / weeksPerTerm）是**全校唯一**的全局结构。
现实中常见：初一初二每天 7 节、初三 8 节；小学部 6 节、初中部 7 节。老软件（自明排课）同样只支持
单一时间结构，学校只能按最多节数建表，低年级最后一节留空 —— 空位会被引擎填入课程，造成"低年级
被加课"的错觉，只能再用"不排时间"逐班手工屏蔽，繁琐且易漏。

## 目标

- 同一项目内允许存在多套作息（TimeScheme），每个班级绑定一套；
- 引擎自动保证：班级课程只落在本班作息的可用节次内；
- 跨方案的合班课、教师冲突、教室冲突依然天然正确；
- 旧项目文件无缝打开（schema 迁移，默认全部班级用同一套作息）。

## 数据模型（sched_core）

```cpp
struct TimeScheme {
    qint64 id = -1;
    QString name;          // "初中部 7 节" / "初三 8 节"
    int daysPerWeek = 5;
    int periodsPerDay = 7;
    int morningPeriods = 4;
    // weeksPerTerm 保持全校统一（学期周数与排课无关，仅打印用）
};

struct ClassInfo : NamedEntity {
    ...
    qint64 schemeId = -1;  // -1 = 使用默认方案
};

struct School {
    ...
    QList<TimeScheme> timeSchemes;  // 至少含 1 套「默认」
};
```

`School::timeConfig` 保留为"默认方案"的读写别名，旧代码路径不受影响。

## 引擎适配（sched_engine）

核心思想：**内部网格取全校并集，按班屏蔽不可用节次**。

1. 内部槽位数 = max(daysPerWeek) × max(periodsPerDay)。绝大多数学校天数相同，
   只是节数不同，并集开销可忽略。
2. 每个班级生成 `可用槽位掩码`：超出本班方案的 (day, period) 一律视为硬禁槽，
   等价于今天的"班级不排时间"，走已有的约束传播通道，零新增冲突逻辑。
3. 合班课：参与班级掩码取**交集**；交集为空（节次完全不重叠）在 precheck 直接报错。
4. 教师 / 教室冲突：按全局槽位索引比较，跨方案天然兼容，无需改动。
5. 软约束里的"上午/下午"判定按**该班方案的 morningPeriods** 解释，而不是全局值。

## 存储迁移（sched_data）

- `PRAGMA user_version` 升到 2：新增 `time_schemes` 表，`classes` 表加 `scheme_id` 列；
- v1 文件打开时：用旧全局 TimeConfig 造 1 套默认方案，全部班级指向它 —— 行为与旧版完全一致；
- Excel 导入模板加可选"作息方案"列，缺省 = 默认方案。

## UI 适配（sched_app / src/ui）

1. **课程设置页**（或新建"作息时间"页）：作息方案列表 CRUD（名称/天数/日节数/上午节数），
   首条为默认方案不可删除；
2. **名单管理-班级**：每班一个"作息方案"下拉列（默认方案）；
3. **新建项目向导**：保留现在的单一时间输入 = 创建默认方案；
4. **课表网格**：按该班方案渲染，超出节次的格子灰显并禁拖；总课表按最大节数渲染，
   各班超出部分画斜纹；
5. **precheck**：新增检查项——"合班课参与班级的可用节次交集为空"给出明确错误；
6. **打印**：班级表按本班节数输出。

## 过渡期建议（现在就能用）

在功能落地前，用现有能力可达到同样效果：按全校最多节数建项目，给低年级班级在
「限制条件 → 不排时间」里把多余节次整行禁掉。引擎会绕开这些格子，课表上也不会出现课程。
（限制条件页已支持整行/整列点选，操作约 10 秒/班。）
